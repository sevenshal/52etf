# 选股交易系统（基本面选股 → 情绪择时 → 技术交易）

把项目里分散的基本面、情绪面、技术面工具串成一条每日流水线。三层分工，不揉成一个总分：

| 层 | 回答的问题 | 更新频率 | 状态 |
|---|---|---|---|
| 基本面股票池 | 选什么 | 每个交易日 19:10（慢变量） | **P1 已完成** |
| 情绪面板块择时 + 仓位控制 | 给多少仓位 | 每个交易日 19:10（紧接股票池） | **P2 已完成** |
| 技术面个股交易 + 模拟盘 | 何时进出、止损在哪 | 每个交易日 19:10（紧接仓位） | **P3 已完成** |

持仓周期定位为**波段**；前期只出信号 + 模拟盘，不自动下单到实盘。

项目自己的研究已经反复说明技术择时以"降回撤"为主、很难"增收益"（见 `research/` 下九转 ATR、
恐贪×九转成分股、支撑压力突破三份结论），所以后续回测必须以**股票池等权买入持有**为基准，
情绪层和技术层各自证明边际贡献，否则关掉。

## P0：地基

- **技术指标后端化**：`backend/src/core/services/stock_system/indicators.py` 逐行移植了 K 线图的
  神奇九转/ATR、MACD、成交量密集区支撑压力、放量 z 值，默认参数与页面一致
  （`compute_chart_indicators` 就是图表的处理流水线）。一致性由共用夹具守着：
  `frontend/src/utils/indicatorParityFixture.js` 生成、`backend/tests/fixtures/stock_indicator_parity.json`
  存档，前端测试断言夹具 == JS 输出，后端测试断言夹具 == Python 输出。**改任何一边的指标算法，
  先改 JS，再 `node frontend/scripts/generate-indicator-parity-fixture.mjs` 重新生成夹具，然后同步 Python。**
  移植时踩到的两处浮点坑：Python 3.12 的 `sum()` 是补偿求和（和 JS 逐个相加末位不同）、
  `round()` 是银行家舍入（和 `toFixed` 不同），模块里分别用 `_js_sum` / `_to_fixed` 复刻 JS。
- **价值投资扫描器 point-in-time**：`as_of` 以前只移动了 beta/估值历史窗口，财报和行情仍读最新值。
  现在财报按披露日截断（缺披露日按报告期后 120 天）、行情/利率/beta 截止到 as_of、上市状态按 as_of
  当时判断（避免后来退市的股票从历史里消失）。as_of 留空（今天）时结果不变。
- **DuckDB 写锁重试**：`duckdb_utils.connect_duckdb_for_write()` 撞锁时有界退避重试，
  `a_stock_base_data_sync._insert_or_replace_analytics_frame` 和股票池快照写入都走它。
- **估值列历史回填**：`a_stock_market_daily` 的 pe/pe_ttm/pb 等是后加的列，生产上 2026-08-25 之前全空。
  定时任务「A股估值列历史回填」（`a_stock_daily_basic_backfill`，默认不定时，需要手动执行一次）
  按交易日拉 tushare daily_basic 只更新这几列，可中断续跑。

## P1：基本面股票池

入口：「研究 → 选股系统」页面；定时任务「选股系统股票池」每个交易日 19:10 计算并按交易日保存快照
（DuckDB `stock_system_pool_run` / `stock_system_pool_snapshot`）。代码在
`backend/src/core/services/stock_system/`。

1. **股票池范围**（`universe.py`）：剔除 ST/退市整理（按当时的简称）、近 5 个交易日平均总市值 < 50 亿、
   平均成交额 < 1500 万。
2. **硬闸门**（从宽，只拦明显有问题的；数据缺失只提示不拦）：最近 12 个月 ROIC < 0、金融股最近 12 个月
   ROE < 3%、盈利但经营现金流为负、资产负债率 > 85%、商誉/归母净资产 > 50%、营收同比 < −30%。
   ROIC/ROE/现金流比都是 TTM 口径（扫描器新输出的 `latest_roic_pct` 等字段），不再用近 5 年平均。
3. **软评分**：10 个因子分四组，每个因子在通过闸门的股票里做截面百分位，按权重合成综合分，取前 N 名入池：
   - 估值：DCF 潜在回报率（复用价值投资扫描器）、卖方共识低估率（最悲观单家目标价下沿）、盈利收益率
   - 成长：营收同比、扣非净利同比、单季营收同比
   - 质量：最近 12 个月 ROIC（金融股用 ROE）、经营现金流/净利润
   - 预期：一致预期增速、目标价中枢 N 日变化（按复权因子换算到同一价格口径）
   - 有值因子的权重占比低于"最低因子覆盖率"时不给综合分。

所有阈值、权重、股票池范围、入池数量都在页面的「参数配置」里改（SQLite `stock_system_configs`），
保存后下一次计算生效。

## P2：情绪择时与仓位控制

入口：「研究 → 选股系统 → 情绪择时与仓位」；同一个定时任务在算完股票池后接着算（也可以只重算这一层）。
代码在 `backend/src/core/services/stock_system/sentiment.py`、`allocation.py`，结果按交易日存
DuckDB `stock_system_regime_snapshot` / `stock_system_allocation_snapshot` / `stock_system_allocation_run`。

- **信号源**：就是「自算贪恐历史曲线」上的顶/底标记——通过 `ETFFearGreedCloneCalculator.load_history_from_db`
  拿到逐日 `signals`（内部是 `compute_turn_signals`，阈值走 `fear_greed_signal_configs`），不另算一套。
- **状态机**：沿历史从后往前找最后一个顶/底标记（与 AI 荐股按中证全指定持仓数同一判定）：底 → 进攻，
  顶 → 防守，没有信号/超过有效期/贪恐数据停更 → 中性。贪恐分数 ≥ 过热阈值（默认 80）时不追新仓。
  信号只依赖当天及以前的数据，历史回放按 as_of 截断即可。
- **个股 → 板块**：成员关系复用雪球持仓表「所属贪恐指数」的同一个函数（≤ 交易日的最新成分权重快照），
  排除宽基/风格指数后取成分股最少、最细分的那条行业指数；只在宽基里的归"未归类"，跟随市场状态。
- **仓位**：市场状态定总仓位上限（进攻 100% / 中性 70% / 防守或过热 40%）；板块过热一律不开新仓，
  板块上限按状态取（进攻 30% / 中性 20% / 防守 0% = 不开新仓，可调大允许防守板块开小仓位）；按股票池排名贪心分配，单只 = min(8%, 总仓位 / 最大持仓数 20)，
  额度不足最小仓位 2% 的跳过、让给其它板块。防守板块里已有持仓不强制卖出（研究显示顶信号清仓离场过早），
  由技术层收紧止损。以上阈值都在「参数配置」里改。
- 九转宽度研究没有发现超额收益，暂不纳入状态判定。

## P3：技术信号与模拟盘

入口：「研究 → 选股系统 → 技术信号与模拟盘」；同一个定时任务在仓位之后接着算。代码在
`backend/src/core/services/stock_system/technical.py`（判定规则）、`trading.py`（编排）、`paper.py`（模拟盘）。

- **输入与口径**：只对第二层分到目标仓位的股票判定入场，外加模拟盘持仓判定出场。K 线用和个股详情页
  同一个加载口径（`load_a_stock_klines_batch`，与单只加载共用行格式，实测逐根相同），指标用
  `compute_chart_indicators`，所以页面上的红绿点、支撑压力线就是判定依据。
- **入场 = 任一触发 × 全部过滤**（逐条可开关、参数可配）：
  - 触发：九转低位反转（最近 N 日内低九后的第一次高二）、回踩支撑企稳（最低价回踩最近支撑 ≤ k×ATR 后收阳）、
    MACD 金叉（可限零轴下方）、放量突破压力（研究无显著优势，默认关）。
  - 过滤：雪球 5 日权价比 ≥ 1.25 且持有组合数 ≥ 8。权价比与「雪球持仓」页同一口径
    （`load_xueqiu_weight_price_ratios` 复用同一段综合权重 SQL、同一个价格源和取整函数，测试断言与历史表逐字段一致）；
    雪球数据 2026-06-25 才开始，快照期数不够、停更的日期自动跳过这条过滤，方便回测时按开关选择。
- **止损与仓位**：止损幅度 = 2×ATR/收盘（夹在 2%~25%）；计划仓位 = min(第二层目标仓位, 单笔风险 1% / 止损幅度)；
  再受市场总仓位、板块上限、最大持仓数和现金约束。
- **出场（任一即卖）**：止损、移动止损（买入后最近红点收盘回撤 ≥ 2 ATR 且出现低 2，板块或市场防守时收紧到
  1.5 ATR）、可选高九止盈、基本面闸门不通过、综合排名跌出 200 名、离开股票池范围。
- **模拟盘**：信号日收盘出单，下一交易日开盘撮合；买单只试一次（停牌、开盘涨停、资金不足一手就撤），卖单遇停牌或
  开盘跌停顺延；分红送转按复权因子折算（不会在除权日假跳水）；佣金 0.03%、卖出印花税 0.05%。账户只往前推进，
  历史日期只算信号。状态存 SQLite `stock_system_paper_*`，信号快照存 DuckDB `stock_system_signal_snapshot`。

## P4：回测与消融

入口：「研究 → 选股系统 → 回测与消融」。代码在 `backtest.py`（回放与统计）、`backtest_workspace.py`（数据工作区）、
`backtest_runner.py`（任务管理）、`src/scripts/stock_system_backtest_worker.py`（子进程入口）。

- **与实盘同一批函数**：调仓日用 `compute_fundamental_pool(as_of=…)` 算股票池（point-in-time）；每天用
  `regime_series/regime_at`（测试断言与 `classify_regime` 逐日一致）+ `build_allocation` 算目标仓位；
  `compute_signals` + `plan_orders` 出信号，`paper.settle` 撮合。技术指标整段历史只算一次、支撑压力按需逐根算
  （`chart_support_resistance_at`，测试断言与图表流水线同一根的值相同）。
- **消融方案**：股票池前 N 等权持有（基准）→ +情绪择时与仓位 → +技术面进出（关雪球）→ 完整系统；再加中证全指买入持有。
  输出总收益、年化、最大回撤、夏普、卡玛、平均仓位、平仓笔数、胜率、盈亏比、分年度收益和净值曲线。
- **第一层验收**：每个调仓日按综合分五等分，看之后 20/60 个交易日的平均收益、高低组价差、秩相关 IC 和 t 值。
- **运行方式**：独立子进程（不占定时任务队列、不抢 API 进程的 CPU），同一时间只跑一个；开始时一张表一张表地
  从生产分析库只读复制所需日期范围到工作区文件（每张表只占几秒锁），之后只读写工作区。历史股票池按第一层参数缓存在
  SQLite，改第二、三层参数重跑不必再算。结果（任务、净值、平仓记录）存 SQLite `stock_system_backtest_*`。
